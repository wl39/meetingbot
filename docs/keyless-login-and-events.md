# 키 없는 접속과 이벤트 로그

일반 실행에서도 주소를 열면 방문자로 자동 연결된다. `.env`의 `STT_KEYLESS_LOGIN=true`와 `.env.rag`의 `RAG_KEYLESS_LOGIN=true`가 기본값이다. 두 값을 `false`로 설정하고 두 서비스를 재시작하면 접속 키가 필요한 방식으로 돌아간다. 데모는 기존처럼 별도 데이터와 한도를 사용한다.

방문자는 자기 파일·실시간 전사, 대본 수정·내보내기·삭제, 공용 자료 검색을 사용할 수 있다. 자료 업로드·관리와 모델·AI 설정, 접속 키 관리는 기존 역할 정책을 따른다. 상단 **관리자 로그인**에서 기존 키를 입력한다. 유효하지 않은 저장 키는 자동으로 제거하고 방문자로 다시 연결한다.

방문자 식별은 브라우저의 HttpOnly·SameSite=Strict 쿠키를 사용한다. HTTPS 공개 origin에서는 Secure 쿠키를 사용한다. 세션 유효 기간은 12시간이며, 쿠키 삭제·만료 후에는 새 방문자로 연결되므로 이전 방문자 기록에 접근할 수 없다. 관리자는 기존 기록을 조회할 수 있다. 쿠키 인증의 변경 요청은 Origin과 CSRF를 계속 검사하며, WebSocket도 방문자 소유권을 검사한다. 기존 파일 300분·4GB와 실시간 5분 한도는 일반 실행에서 유지된다.

## 저장 위치

- STT: `STT_DATA_DIR/logs/events.jsonl` (이 설치에서는 프로젝트의 `.runtime/logs/events.jsonl`).
- RAG: `RAG_DATA_DIR/logs/events.jsonl` (이 설치에서는 `~/Library/Application Support/MeetingbotRAG/data/logs/events.jsonl`).
- 서비스별 10MiB 파일과 이전 파일 5개, 합계 약 60MiB까지 순환 보관한다. 용량을 넘으면 가장 오래된 파일부터 교체한다. 날짜 기준 영구 보관은 아니다.
- 로그 파일 권한은 `0600`이다. 웹에서 파일을 내려받는 공개 API는 제공하지 않는다.

```sh
tail -f .runtime/logs/events.jsonl
```

## 기록 범위

| 구간 | 이벤트 |
|---|---|
| HTTP | 모든 요청의 시작·종료, 메서드, 라우트 템플릿, 상태 코드, 처리 시간, 예외 종류. 인증·권한·Origin·호스트 거부와 유효성 검증 실패 포함 |
| 로그인 | 세션 발급, 잘못된 키 사용, 로그아웃, 키 발급·폐기, 할당량 거부 |
| STT | 세션 생성·갱신·삭제, 작업 상태, 경고, 부분·확정·수정·철회 발화의 ID와 revision, 백그라운드 작업 종료 |
| 실시간 | WebSocket 시작·종료, 각 수신·송신 메시지 유형과 바이트 수, 종료 코드 |
| RAG | 데이터 변경 테이블·작업 종류·영향 행 수, 트랜잭션 commit/rollback, 색인 작업 생성·진행·종료 |
| 모델 관리 | 설치·선택 작업의 상태와 단계 변경 |
| 브라우저 | 화면 이동, 클릭, 값 변경 발생, 폼 제출, 미디어 재생·일시정지·탐색·종료, 실행 오류·처리되지 않은 Promise 오류, 페이지 종료 |
| 서비스 | 시작과 정상 종료, STT 워커 준비·준비 실패 |

각 행은 UTC `timestamp`, 고유 `id`, `service`, `event`를 포함한다. 요청은 `request_id`로 연결하며 응답의 `X-Request-ID`에도 표시한다. STT에서 RAG로 전달된 요청은 RAG의 `parent_request_id`로 연결할 수 있다. 인증 이후에는 방문자/키의 내부 식별자와 역할을 포함한다. RAG 트랜잭션 내부의 변경은 `pending`으로 기록되고 동일한 `transaction_id`의 commit/rollback으로 실제 결과를 구별한다.

로그에는 접속키·쿠키·CSRF·요청/응답 본문·검색어·대본·문서·파일명·쿼리 문자열·예외 메시지를 저장하지 않는다. 브라우저 동작은 화면 종류와 DOM 요소의 구조적 위치만 저장하며 입력한 값과 화면 문구는 저장하지 않는다. 오디오 WebSocket도 실제 바이트를 저장하지 않는다. 정상 종료를 거치지 않은 프로세스 종료는 `service.stopped`가 없을 수 있다.

브라우저 로그는 2초마다 최대 50개씩 전송한다. 인증 전에는 최대 100개를 메모리에 대기시키며 초과 시 오래된 이벤트를 버린다. 연결 실패·브라우저 강제 종료·서버의 수집 한도에서는 일부 화면 이벤트가 유실될 수 있다. 키 입력 하나하나나 마우스 이동은 수집하지 않는다. 서버 요청과 작업 로그는 브라우저 전송 여부와 별도로 기록된다. `/api/events`는 인증·CSRF와 32KiB 본문/50개 배치 제한을 적용한다.

## 검증

- STT: 키 없는 정상 전사·내보내기, 다른 방문자 기록/스트림 차단, CSRF, 잘못된 키, 로그아웃 및 키 전용 모드.
- RAG: 직접 접속 시 방문자 세션, 권한·CSRF 검사, 로그아웃 및 키 전용 모드, 로그의 트랜잭션 구분.
- 로그: 요청 거부·500 오류·브라우저 이벤트·전사 작업 기록, 라우트 템플릿, 본문·키 제외, 순환 보관·파일 권한.
- `scripts/keyless_ui_smoke.mjs`: 격리한 모의 STT/RAG 서버에서 Chrome으로 자동 접속, 자료 검색 진입, 관리자 로그인/로그아웃, 오래된 키 복구, 화면 로그 전송을 검사한다. 실제 음성 모델 정확도 검증은 아니다.
