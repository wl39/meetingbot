# 사용자 화면의 문구 원칙

회의봇은 문서를 등록하고 질문하며, 회의를 기록하고 발언 내용을 기존 문서와 대조하는 서비스다. 사용자 화면은 이 업무 흐름과 결과를 설명한다.

- 주요 동작: 문서 등록, 질문하기, 문서 검색, 원문 보기, 회의 검토 시작.
- 모델 이름, 제공자, 실행 장비, 추론 옵션, 임베딩, 청크, 내부 오류 코드, 외부 전송 승인 절차를 일반 화면에 표시하지 않는다. 운영자 전용 설정에서 필요한 경우에만 다룬다.
- 예: ‘연결된 AI로 전송합니다’ 대신 ‘등록된 문서를 바탕으로 답변하고, 확인에 사용한 출처를 함께 제공합니다.’
- 예: ‘안정된 발화에서 실무 키워드 추출’ 대신 ‘회의에서 나온 내용을 문서와 대조합니다.’
- 검토 결과는 ‘문서와 일치’, ‘문서와 차이 있음’, ‘확인 필요’, ‘참고 정보’로 표현한다. 문서와의 일치를 사실의 절대적인 진위 판정으로 표현하지 않는다.
- 오류는 사용자가 다음에 할 일을 설명한다. 내부 오류 코드는 운영 진단에 남기고, 기존 질문 기록에 포함된 기술적 오류 문구도 화면에서는 서비스 문구로 바꿔 표시한다.
- 문서의 내용은 그대로 보존한다. 사용자가 작성한 문서 안의 기술 용어는 삭제하거나 바꾸지 않는다.

문서 질문과 회의 검토를 시작할 때 관리자는 해당 문서의 이용 설정을 활성화할 수 있다. 서버의 권한 및 이용 설정 검증은 유지하며, 방문자가 관리자의 설정을 변경할 수는 없다.

Markdown은 원문 창뿐 아니라 검색 결과의 문서 발췌와 회의 검토의 인용에서도 렌더링한다. 원문 창은 목차, 표, 목록, 코드, 같은 문서 모음 안의 링크, 줄 번호 보기와 이전 문서 탐색을 지원한다. 내부 파일 경로나 다른 워크스페이스를 링크로 열지 않는다.
