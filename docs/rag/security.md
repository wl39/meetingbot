# RAG 보안 경계

방문자·관리자·슈퍼관리자 역할을 서버에서 검사한다. 로그인하지 않은 방문자도 브라우저 세션으로 파일·폴더를 업로드해 개인 워크스페이스를 만들고 자신의 자료를 관리할 수 있다. 개인 자료는 소유 방문자와 관리자만 볼 수 있으며, 기존 공용 자료는 방문자도 검색하고 질문할 수 있다. 관리자는 공유 폴더 연결과 전체 자료 업로드·삭제·색인 및 공간 관리, 슈퍼관리자는 모델·AI 연결·전역 설정과 키 관리를 수행한다. 기업용 문서별 ACL은 제공하지 않는다. 기존 로컬 관리자 키는 슈퍼관리자 키다. 키 발급·폐기는 통합 웹의 접속 및 권한 화면에서 수행한다.

역할 키와 브라우저 세션은 공통 AccessStore에 해시로 저장한다. 키 기반 세션은 12시간 후 만료한다. 방문자 세션은 30일이며 유효한 접속 확인 시 갱신한다. 폐기된 키의 세션도 다음 요청부터 거절한다. 기존 부트스트랩 키가 바뀌면 이전 키의 세션도 무효화한다. RAG 독립 로그인은 HttpOnly/SameSite=Strict `/api/rag` 쿠키를, 통합 데모는 HttpOnly/SameSite=Strict `/` 방문자 쿠키를 사용한다. 공개 HTTPS의 방문자 쿠키는 Secure다. 쿠키를 사용하는 변경 요청은 허용 Origin과 CSRF 토큰을 검증하며 잘못된 Bearer는 다른 쿠키로 대신 인증하지 않는다.

기본은 loopback이며 개인 인스턴스는 Tailscale Serve 내부 접속을 유지한다. 데모는 별도 데이터·키·샘플 문서를 사용하고 선택적으로 Funnel 10000 포트에 공개한다. 방문자는 자신의 질문 이력만 볼 수 있다. 관리자 전체 조회와 계정별 기록 정책은 [질문 기록](question-history.md)을 따른다. 상세한 실행·일일 한도·자료 정리는 [공개 데모](../public-demo.md)를 참고한다.

로그인은 10회/분/IP, 일반 API는 인증 식별자별 240회/분, 파일 PUT은 식별자별 6,000회/분 제한이다. 식별자는 인증 검증을 거쳐야 하며 버킷 수도 제한한다. 검색 2개, LLM 1개, 색인 작업자 1개와 큐 최대 4개의 기존 동시성 제한은 유지한다. reverse proxy는 loopback만 신뢰한다.

파일 경계:

- 서버 폴더 연결은 root_id + relative_path만 전송한다. 외부 기기 업로드는 상대 파일 경로와 파일 본문을 전송한다. 서버 절대 경로를 반환하지 않는다.
- 모든 조상 디렉터리와 최종 파일을 `dir_fd` + `O_NOFOLLOW`로 열어 링크 교체에 의한 우회를 막는다. 문자열 prefix로 경계를 판단하지 않는다.
- 절대 경로, `..`, `%`를 통한 중첩 인코딩, 역슬래시, 제어 문자를 거절한다. 퍼센트가 실제로 들어간 파일명도 MVP에서 제한한다.
- 심볼릭 링크, 하드 링크 파일, 장치/소켓/FIFO, 숨김·임시·인증 파일, 모델·앱 데이터 경로를 제외한다. 디렉터리 제외 정책은 재귀 진입 전에 적용한다.
- 연결된 서버 원본은 읽기만 한다. 업로드 사본은 앱 전용 저장소에서 관리하고 공간 삭제 시 함께 지운다. 허용 루트 설정은 웹/LLM에서 변경할 수 없다. root_id에 매핑된 실제 경로가 바뀌면 기존 연결을 재사용하지 않는다.
- 조회 시에도 허용 루트와 현재 폴더 읽기 권한을 검사한다. 회수되면 보관된 스냅샷과 질문 기록 조회를 차단한다. 이미 브라우저/외부 LLM으로 전달된 데이터는 회수할 수 없다.
- XLSX는 압축 해제량/시트/행/열/셀 제한, DOCTYPE 거절, 외부 링크 비활성화, 매크로 거절. 수식은 실행하지 않는다.

브라우저는 문서 내용을 일반 텍스트로 렌더링한다. 임의 HTML/Markdown 스크립트, 원격 이미지와 문서 URL을 자동 로드하지 않는다. CSP는 self script/connect, frame-ancestors none, base-uri none이다. 일반 로그에는 요청 본문/전체 질문/답변/키를 쓰지 않으며 LangSmith tracing은 코드에서도 끈다. 유효하지 않은 요청의 입력값을 오류 응답에 반사하지 않는다.

한계: OS 관리자나 서비스 계정 자체가 공격당하면 디스크 자료를 보호할 수 없다. 일반 로그에서 원문을 생략하는 정책은 모델 가중치 로딩 메시지와 별개다. SSD/APFS에서 앱 파일 삭제는 저장매체의 포렌식 완전 삭제를 보장하지 않는다. 백업도 별도로 관리해야 한다.


AI 설정은 단일 관리자가 변경한다. 웹에서 저장한 연결 키는 일반 응답에 재노출하지 않으며 SQLite에 보관하므로 데이터 디렉터리와 백업을 비밀 자료로 취급한다. 새 연결 주소에는 기존 키를 자동 전송하지 않는다. LangSmith tracing은 비활성화하고 도구 호출은 설치하지 않는다. 프롬프트 출력은 JSON 구조·허용 status·실제 근거 ID를 검증한다. 이는 자연어 답변의 의미적 정확성을 보장하지 않는다.

관리형 CLIProxyAPI는 `127.0.0.1:8317`에만 바인딩하고 별도 랜덤 API/관리 키를 사용한다. 설정·키·OAuth 인증 디렉터리는 사용자 계정 전용 권한으로 보호한다. 관리 UI 자동 다운로드, 원격 관리, 플러그인, pprof, 사용량 통계를 끈다. `commercial-mode: true`로 요청 로깅 미들웨어 자체를 설치하지 않게 설정했다. `request-log: false`만으로는 upstream의 오류 요청 본문 로그까지 막지 못하므로 이를 함께 적용한다. SDK 호출은 프록시만 사용하며 프록시가 계정의 Codex 서비스에 요청을 전달한다.

RAG의 Codex 인증 API는 고정된 loopback 관리 주소로만 호출한다. 범용 관리 API 프록시를 노출하지 않는다. 관리 키·OAuth access/refresh token을 브라우저에 전달하지 않는다. 로그인 URL은 auth.openai.com HTTPS만 허용하고, 수동 callback은 현재 발급된 state와 정확한 localhost:1455/auth/callback 주소를 요구한다. callback 주소/인증 코드는 RAG DB·질문 기록·일반 로그에 저장하지 않는다. 프록시가 OAuth token 교환과 갱신을 담당한다.

외부 폴더 업로드는 [업로드 계약](folder-upload.md)을 따른다. 내부 업로드 루트만 앱 데이터 경로 제외 정책의 예외이며, 서버 발급 ID의 사본만 읽는다. 서버 폴더 등록 API를 통한 내부 루트 재연결은 차단한다. 업로드 자료에도 기존 원문 조회의 O_NOFOLLOW와 파서 자원 제한을 적용한다. 같은 접속 키를 가진 사용자는 모든 공간을 관리할 수 있으며, 업로드 기능은 사용자별 ACL을 추가하지 않는다.
