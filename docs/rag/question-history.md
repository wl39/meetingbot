# 계정별 질문 기록

자료 검색의 왼쪽 메뉴에서 **내 질문 기록**을 열면 현재 접속 계정의 AI 질문과 문서 검색을 다시 볼 수 있다. 각 기록에는 질문 ID, 요청 시각, 사용한 자료와 버전, 질문·답변, 인용 출처가 저장된다. 상세 화면의 URL에는 질문 ID만 남으므로 새로고침해도 같은 기록을 연다. ‘이 자료에서 이어 질문하기’는 기존 답변을 복원하며 AI를 다시 호출하지 않는다.

관리자와 운영 관리자는 **전체 질문 기록**에서 계정, 자료, 질문/검색 유형, 기간, 질문·답변 검색어로 필터링하고 페이지를 넘겨 조회한다. 계정명은 접속 키 발급 시 지정한 이름이며, 방문자는 서버에서 발급한 방문자 ID로 구분한다. 계정 ID와 이름·역할은 질문 시점의 로그인 정보로 서버가 기록한다. 클라이언트가 전달한 임의의 계정 ID로 소유권을 정하지 않는다.

질문 본문을 localStorage에 복사하지 않는다. 실제 기록은 RAG SQLite `query_runs`에 저장하고, 방문자는 HttpOnly/SameSite 쿠키의 서버 발급 식별자로 자신의 기록을 찾는다. 방문자 쿠키는 30일이며 유효한 접속 확인 시 갱신된다. 브라우저 데이터를 지우거나 로그아웃하면 해당 방문자 식별자가 제거된다. 접속 키 계정은 동일한 키로 재접속하면 기존 계정의 기록을 조회한다. 키 기반 로그인 세션의 기존 12시간 만료·키 폐기 정책은 유지한다.

기존 보관 정책을 유지한다: 기본 최근 30일, 공개 데모 최근 1일이며 화면에 기간을 표시한다. 자료 또는 버전 삭제 시 연결된 기록도 기존 정책대로 삭제한다. 허용 원본의 접근 권한이 회수되면 기록의 목록·검색·상세·출처 조회에서도 내용을 차단한다. 일반 사용자는 다른 사용자의 질문 ID를 알아도 조회할 수 없다.

이전 버전에서 저장한 기록은 답변을 보존하되 소유자를 추정하지 않는다. 관리자 전체 조회에 ‘이전 기록 · 계정 미확인’으로 표시한다. 신규 요청은 검색/AI 처리 전에 저장하므로 모델 연결 실패나 처리 중 서버 재시작도 기록에서 구분된다.

검증: `rag/tests/test_query_history.py`, `rag/tests/test_access.py`, `backend/tests/test_access.py`, `scripts/rag_question_history_smoke.mjs`.
