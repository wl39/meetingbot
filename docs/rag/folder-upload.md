# 외부 기기의 폴더 업로드

회의봇의 **자료 검색**에서 기존 접속 키로 로그인한다. **워크스페이스 만들기 → 내 기기 폴더 업로드 → 폴더 선택**에서 자료를 고른다. 목록은 파일 이름 아래에 폴더 아이콘과 상대 폴더 경로를 표시한다. 파일별 체크박스와 **전체 선택 / 전체 해제**로 업로드 대상을 정하고 **업로드하고 자료 준비**를 누른다. 파일 수·용량 한도는 체크한 지원 파일과 그 하위 폴더만 계산한다. 200개를 넘는 목록은 **파일 더 보기**로 계속 확인할 수 있다.

좌측 목록에 **대기 중 / 업로드 중 / 업로드 완료 / 전송 실패**가 표시된다. 재시도는 서버가 수신 완료한 파일을 건너뛴다. 전송 완료 후에도 결과를 확인할 수 있도록 화면을 유지하며 **워크스페이스 열기**로 이동한다. 색인은 자동 시작되며 파일 전송 완료와 검색 준비 완료는 별개다. 대기열이 가득 차면 업로드한 파일은 보관되고, ‘자료 새로고침’으로 색인을 다시 시작할 수 있다.

MD 검색 근거의 **원문 보기**는 제목·목록·표·코드를 렌더링한 문서로 열린다. **원문 · 줄 번호**에서 원래 Markdown과 근거 줄 강조를 확인한다. HTML 실행과 외부 이미지 자동 로드는 하지 않는다.

검색 화면의 **질문하기**로 문서 기반 답변과 출처를 확인한다. 관리자가 질문이나 회의 검토를 시작하면 필요한 문서 이용 설정을 적용하며, 저장이 성공한 경우에만 요청을 진행한다. 방문자가 관리자의 이용 설정을 바꿀 수는 없다. 연결과 모델의 기술적 설정은 운영 관리자 전용 화면에서 관리하고, 일반 화면에는 노출하지 않는다.

하위 폴더 경로와 원문 위치를 보존한다. 브라우저의 폴더 선택은 `webkitdirectory`/`webkitRelativePath`를 사용한다([MDN](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)). 지원되지 않는 환경에서는 **파일 선택**으로 여러 파일을 올릴 수 있다. 빈 디렉터리는 보존하지 않는다. ZIP 해제 업로드는 제공하지 않는다.

현재 지원: MD, TXT, CSV, TSV, XLSX. 기본 한도는 파일당 10 MiB, 폴더 합계 100 MiB, 파일과 하위 폴더 합계 2,000개다. 전송 대상 파일은 이름을 포함하여 경로 11단계 이하다. 숨김·인증·임시 파일, node_modules 등과 미지원 형식은 전송 전 제외 목록에 표시한다. 서버도 경로·확장자·크기·중복을 다시 검증한다. 텍스트 인코딩과 표 형식은 기존 파서 제한을 적용하며, 파싱 실패는 자료 관리에서 확인한다.

진행률과 현재 파일을 표시하며, 연결 중단 시 같은 화면에서 **이어서 재시도**하면 이미 수신한 파일은 재전송하지 않는다. 취소 또는 등록 화면을 벗어나면 미완료 전송 정리를 요청한다. 새로고침·탭 종료 시 같은 파일을 다시 선택해야 한다. 남은 미완료 업로드는 생성 24시간 후 정리한다. 서버 재시작에도 완료한 파일과 수신 상태가 유지된다.

자료는 서버 사본이다. 기기의 원본을 수정해도 자동 동기화되지 않는다. 수정 자료는 새 워크스페이스로 다시 올린다. 업로드 워크스페이스를 삭제하면 서버 사본·색인·스냅샷·질문 기록을 함께 삭제한다. 원래 기기의 파일은 유지된다. 서버 허용 폴더 연결 방식은 기존처럼 읽기 전용이다. 백업에는 업로드 사본도 포함되므로 별도 보관 정책을 적용한다.

현재는 **단일 관리자 접속 키**를 사용하는 공유 서비스다. 사용자별 개인 계정이나 별도 접근 권한은 없다. 접속 키를 공유하는 사용자는 업로드한 자료를 볼 수 있다. 업로드만으로 외부 LLM 전송을 승인하지 않는다. 생성 후 워크스페이스 설정에서 명시적으로 허용해야 AI 답변을 사용할 수 있다. 로컬 근거 검색은 이 승인 없이 동작한다.

## 저장 및 운영

- `RAG_DATA_DIR/upload-staging/<무작위 ID>`: 전송 중 파일. 클라이언트 이름 대신 서버 발급 파일 ID로 저장한다.
- `RAG_DATA_DIR/uploaded/<무작위 ID>`: 완료된 폴더 트리. SHA-256·크기를 확인한 뒤 게시하며 SQLite 트랜잭션으로 워크스페이스를 만든다. 완료 API는 재시도해도 같은 워크스페이스를 반환한다.
- 스키마 v3 `upload_sessions`: 목록, 크기, 수신 여부, 만료 및 워크스페이스 연결. 기존 설정·프롬프트·자료를 보존하며 자동 마이그레이션한다.
- 업로드 저장 기본 한도 1 GiB(`RAG_UPLOAD_STORAGE_BYTES`), 진행 중 세션 최대 3개, 파일 전송은 직렬화한다. 이 한도는 원본 사본과 예약량 기준이며 색인·스냅샷·백업 용량을 포함하지 않는다. 파일당 120초 전송 제한이 있다.
- `RAG_UPLOAD_SESSION_HOURS=24`, 기존 `RAG_MAX_FILE_BYTES`, `RAG_MAX_TOTAL_BYTES`, `RAG_MAX_FILES`, `RAG_MAX_DEPTH` 설정으로 제한을 조정한다.
- 원시 파일 PUT만 별도 6,000회/분 제한을 적용한다. 관리자 인증, HTTPS, Host/Origin 및 CSRF 검사는 동일하다. 다른 API는 기존 240회/분이다. 파일 본문은 스트리밍으로 수신하며 실제 바이트 수를 확인한다.

검증: `rag/tests/test_uploads.py`, `frontend/src/features/rag/folder-upload.test.ts`, 실제 설치 결과 `folder-upload-test-results.json`. 브라우저 화면 검증 및 다른 물리 기기의 네트워크 검증 여부는 결과 파일에 구분하여 기록한다.
