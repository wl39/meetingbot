# 현재 한계와 다음 검증

## 아직 완료로 볼 수 없는 항목

1. Community-1 다운로드와 CPU 로드/추론을 완료했고, 1인 한국어 합성 음성에서 화자 한 명을 배정했습니다. OS 네트워크 차단 상태에서도 성공했습니다. **실제 다인 회의의 화자 분리 정확도는 아직 검증하지 않았습니다.**
2. 실시간 PCM/VAD/Whisper 경로는 짧은 합성 음성으로 확인했습니다. 하드웨어 마이크, 5분 연속 입력과 화자 20초 누적 분석의 실제 계산량은 검증하지 않았습니다. 마이크 음질·브라우저 AudioContext·권한·오디오 장치별 테스트가 필요합니다.
3. 짧은 실시간 창의 인식 결과는 파일 전체 전사보다 품질이 낮았습니다. 실시간 단어 누락과 기술어 오인식을 정답 코퍼스로 진단해야 합니다. 수동 교정은 가능하지만 LLM 교정/요약은 제공하지 않습니다.
4. 1~8명 선택값은 입력 설정 범위이며 화자 정확도 보장이 아닙니다. 임베딩 추적·세션 간 음성 신원 확인·겹친 음원의 복원은 구현하지 않았습니다.

## 구현상의 초기 선택

- 실시간 ASR은 최대 12초 창, 1초 중첩, 2초 재평가를 사용합니다. 작업이 밀리면 중간 발화를 건너뛰지 않고 순서대로 처리합니다. VAD로 확인한 무음은 원래 오디오 시간을 유지하며 추론을 생략합니다.
- stable은 시점 기준의 안정화 결과입니다. 사용자 수정과 후속 화자 재분석으로 더 높은 revision이 올 수 있습니다. 타임스탬프는 Whisper attention 기반이며 강제 정렬 결과가 아닙니다.
- 화자 분석은 전체 누적 오디오를 20초마다 요청하고 이전 분석이 끝나기 전 추가 작업을 큐에 쌓지 않습니다. 다음 실행 시 최신 스냅샷을 사용합니다. 배치 결과 라벨은 비중첩 발화 시간의 상호 우세 기준으로 세션 ID에 매핑합니다. 모호한 분할·병합과 350ms 미만 근거는 미확정으로 남길 수 있습니다. 실제 정확도는 미측정입니다.
- 수동 수정 구간은 이후 재분할로 소실되지 않도록 경계를 보존합니다. 수정하지 않은 텍스트/화자 필드는 자동 갱신을 허용합니다. 한 수동 구간에 여러 화자가 분석되면 자동 화자는 미확정이 될 수 있습니다.
- WebSocket은 개별 변경 이벤트 대신 0.5초 주기의 최신 대본 스냅샷을 보냅니다. stable/corrected/retracted 영구 이벤트 이력은 별도 endpoint와 JSON export에 들어 있습니다.
- Session에 speakers/최신 utterances를 JSON으로 보관하고, jobs/events는 별도 SQLite 테이블을 사용합니다. 파일 상한은 300분·4GB로 확장했으며 단일 사용자 구조입니다. 다중 사용자·장시간 로그 탐색에 맞춘 DB 정규화는 하지 않았습니다.
- 취소는 현재 DELETE와 동일하여 대본과 관리 원음도 삭제합니다. 실행 중인 모델을 즉시 선점하지 않으며 끝날 때까지 다음 작업을 잠급니다. 추론 프로세스 자체가 무한 정지하는 경우 강제 워커 재기동 UI는 아직 없습니다.
- 파일 전사 진행률은 완료된 2분 구간의 오디오 길이를 기준으로 표시합니다. 화자 분석은 단계로 표시합니다. 실시간 측정은 첫 자막/첫 stable 시점, 처리 완료 위치, 뒤처진 오디오, 추론 시간, PCM 버퍼 크기 중심입니다. 발언별 지연 분포와 전체 프로세스 RSS는 추가 계측 대상입니다.
- 파일 오디오는 디스크 memmap으로 처리하여 전체 PCM을 워커 사이에서 복사하지 않습니다. 화자 군집 학습은 최대 4,096개 임베딩을 시간대 전반에서 표본화하고 전체 임베딩에 화자를 배정합니다. 장시간 녹음의 드문 화자·화자 정확도는 추가 검증 대상입니다. 300분 입력 허용은 해당 길이 실제 회의의 정확도나 처리 시간 보장을 뜻하지 않습니다.
- 한 프로세스의 API 인스턴스에 ASR/화자 워커 각 1개를 둡니다. 여러 uvicorn worker나 서버 인스턴스를 같은 데이터 폴더로 실행하지 마세요.
- 원음 보관은 기본 비활성화입니다. 파일 입력은 임시 디스크 저장이 필요하고 실시간 입력은 상한 내 메모리를 사용합니다. 삭제는 논리적 파일/DB 삭제이며 디스크 포렌식 복구 불가능성이나 OS swap 부재를 보장하지 않습니다.

## 다음 작업 순서

2인 이상 실제 한국어 파일의 전사/화자/원본 시간축 사람 검증 → 실제 마이크 1분·5분과 짧은 “네/아니요” 확인 → 긴 무음·겹침·숫자/영문 기술어 코퍼스 → CER/DER과 지연·메모리 보고 → 모델/화자 매핑 개선. 이를 수행하기 전에는 화자 분리 포함 MVP 전체의 실사용 검증이 완료되었다고 보고하지 않습니다.

## Tailscale 확장 (사용자 요청)

원 설계의 localhost 전용 범위에서 확장하여 Tailscale Serve의 HTTPS/원격 WebSocket을 지원합니다. API loopback 바인딩과 접속 키 인증은 유지합니다. 설정/운영 방법은 [HF와 Tailscale 안내](hf-and-tailscale.md)를 참고하세요.
