# M4A 업로드 실패 조사 및 수정 — 2026-09-09

기존 실패 세션은 snapshot_revision=4이며, 생성 → PREPROCESSING → FAILED → warning 순서와 일치한다. 저장된 예외는 ValueError뿐이다. 이전 디코더의 재생시간/디코딩 결과 검증에서 실패한 것으로 범위를 좁혔지만, 구체적인 조건은 과거 기록으로 구분할 수 없다. 원음 미보관 설정으로 입력 파일도 정리되어 사용자 파일의 원인은 아직 확정되지 않았다.

수정 사항:

- 컨테이너 재생시간이 없거나 N/A이면 스트림 재생시간을 확인하고, 그것도 없으면 제한된 길이만 디코딩하여 실제 샘플 수로 검증한다.
- 기존 600초 제한은 유지한다. 메타데이터가 없어도 디코딩 길이로 제한 초과를 감지한다.
- 파일 길이 초과, 읽기/변환 실패, 오디오 없음, 시간 초과, 변환 도구 누락을 구분하여 작업 기록과 한국어 안내에 표시한다.
- 로그에 세션 ID, 실패 단계, 오류 코드, 길이만 남긴다. ffmpeg의 원문 stderr나 원음/대본은 기록하지 않는다.

검증:

- 백엔드 45개 테스트 통과. AAC·ALAC M4A 업로드, N/A/누락/0/NaN 길이 처리, 길이 제한 우회 방지, 오류 사유 전달 포함.
- 프런트엔드 3개 테스트 및 프로덕션 빌드 통과.
- 수정 전 디코더에서도 정확히 600초 AAC M4A가 정상 디코딩됨을 확인했다. M4A 전체에 영향을 주는 형식 호환성 문제는 재현되지 않았다.
- 배포 후 Tailscale HTTPS 주소로 48kHz 스테레오 AAC·ALAC M4A를 업로드했다. 각각 5.82025초 합성 한국어 음성이 실제 Whisper + Community-1 처리에서 COMPLETED, 경고 없음으로 종료되었다. 생성한 진단 세션은 삭제했다.

남은 확인: 사용자가 실패한 원본 M4A를 다시 업로드하여 정확한 오류 또는 성공 여부를 확인해야 한다. 이번 변경으로 과거 실패 원인이 확정되거나 해당 원본이 검증된 것은 아니다.

## 추가 확인 및 한도 확장

상세 기록 적용 후 새 업로드에서 `AUDIO_TOO_LONG`, `duration_seconds=4251.605333`, `max_seconds=600`이 확인됐다. 이 업로드의 실패 원인은 약 70분 52초 녹음이 기존 10분 제한을 초과한 것이다. 사용자의 후속 요청에 따라 현재 파일 상한은 300분·4GB로 확장했다. 위 10분 제한과 기존 코드 설명은 조사 당시 상태이며 현재 설정이 아니다.
