# 300분 파일 및 Turbo 지원 — 2026-09-09

파일 업로드 한도를 18,000초(300분), 4,294,967,296바이트(4GiB)로 확장했다. 서버 설정, HTTP 전체 요청 제한, 업로드 검증, health 응답, 프런트엔드 표시/검증에 같은 값을 사용한다. 마이크 입력은 기존 300초다.

`large-v3-turbo` 모델을 다운로드하여 small과 함께 선택할 수 있다. 모델은 `mlx-community/whisper-large-v3-turbo`, revision `a4aaeec0636e6fef84abdcbe3544cb2bf7e9f6fb`이다. 서버에는 두 모델과 Community-1의 준비 상태를 확인했다. 추론은 로컬 모델로 실행한다.

## 장시간 처리 방식

- 입력은 FFmpeg로 임시 float32 PCM 파일에 디코딩한다. 메모리 맵으로 접근하며 전체 PCM을 프로세스 간에 복사하지 않는다. 정확히 300분인 16kHz 모노 PCM은 1,152,000,000바이트다.
- ASR은 중앙 120초 구간과 양쪽 최대 2초 문맥을 사용한다. 단어 중간 시각으로 구간 소유권을 결정하고 원본 시간축에 합친다. 구간이 완료될 때마다 중간 대본과 전사 진행률을 저장한다. 문맥 경계의 실제 인식 정확도는 회의 자료로 추가 평가해야 한다.
- 화자 분석은 전체 오디오를 대상으로 한다. 사용 가능한 GPU(CUDA → Apple MPS)를 자동 선택하고 없으면 CPU를 사용한다. CPU 스레드는 기본적으로 논리 코어의 절반(최대 8), 모델 배치는 8이며 환경 변수로 변경할 수 있다. VBx의 초기 AHC 학습 표본은 전체 시간대에서 최대 4,096개를 선택하여 거리 행렬 크기를 제한하고, 모든 임베딩에는 최종 화자를 배정한다. 이 방식은 화자 번호를 구간마다 초기화하지 않지만 드물게 등장하는 화자의 정확도에 영향을 줄 수 있다.
- 원음 보관 시 WAV 변환도 작은 구간으로 저장한다. 완료/실패/취소 후 임시 입력과 PCM을 정리하고, 서비스 재시작 시 중단된 작업의 임시 PCM도 정리한다.
- 대본 조립과 화자 시간 구간 처리를 정렬된 구간 탐색으로 바꾸고 기존 대본 매칭에 시간 버킷을 사용한다.

## 검증

- 백엔드 50개 테스트, 프런트엔드 3개 테스트, 프런트엔드 프로덕션 빌드 통과.
- 실제 FFmpeg로 300분 FLAC을 디코딩하여 정확히 18,000초, 288,000,000개 샘플을 확인했다. 18,001초 파일은 `AUDIO_TOO_LONG`으로 거부했다.
- 300분 무음 FLAC 업로드를 모의 ASR/화자 엔진으로 전체 실행해 COMPLETED, 처리 위치 18,000초, 임시 파일 정리를 확인했다. 이는 실제 모델 5시간 추론 테스트와 다르다.
- 구간 경계 문맥 중복 제거, 절대 타임스탬프, memmap 워커 전달, 군집 표본 상한과 원래 인덱스 대응을 회귀 테스트로 확인했다.
- 합성 300분 대본(54,000단어, 3,600발언)은 조립 0.178초, 최초 저장과 동일 결과 재발행 합계 0.108초였다. 모델 추론이나 실제 회의 정확도 측정이 아니다.
- 실제 Turbo와 Community-1의 Tailscale 업로드 검증 수치는 [실행 기록](turbo-long-smoke.json)에 저장했다. 5.82025초 M4A는 5.77초에 완료됐다. 11분 M4A(합성 한국어 반복 및 무음)는 전사 82.85초, 화자 분석 710.10초, 전체 793.43초에 COMPLETED로 종료됐고 경고가 없었다. 테스트 세션은 삭제했다. 실제 회의나 전체 300분 실모델 벤치마크가 아니다.

실제 300분 회의의 전체 처리 시간과 다인 화자 정확도는 아직 측정하지 않았다. 긴 작업은 단일 활성 작업 슬롯을 사용하며 Mac이 깨어 있어야 한다.


## GPU 및 화자 분석 진행률 (2026-09-15)

- `STT_DIARIZATION_DEVICE=auto|mps|cuda|cpu`, `STT_DIARIZATION_CPU_THREADS=0`(자동), `STT_DIARIZATION_BATCH_SIZE=8` 설정을 지원한다. 현재 M1에서는 MPS GPU + CPU 보조 스레드 4개를 선택한다. 화자 묶기 등 일부 후처리는 CPU에서 수행한다.
- 모델의 segmentation/embeddings hook에서 실제 완료 개수와 전체 개수를 받아 0.5초 간격으로 작업 프로세스 → 서버에 전달한다. 화면은 현재 단계의 비율, 처리 개수, 장치, 경과 시간을 표시한다. 화자 묶기와 결과 정리는 전체 개수가 없으므로 비율을 표시하지 않는다. 전체 완료 예상 시간으로 환산하지 않는다.
- 가속기 관련 추론 실패는 CPU로 한 번 재시도하며 화면에 전환 사실을 표시한다. 자동 재시도는 반복하지 않는다. 지원되지 않는 일부 MPS 연산은 PyTorch의 CPU fallback을 허용한다.
- 전사 완료 시 단어/시각 및 PCM을 임시 체크포인트로 보관한다. 비정상 서비스 재시작 시 같은 세션의 화자 분석부터 재개한다. 기존 화자 분석의 내부 계산은 다시 시작하며 텍스트 전사는 반복하지 않는다. 정상 종료 시 임시 체크포인트/PCM은 정리한다. 체크포인트 없는 이전 작업은 기존대로 INTERRUPTED 처리한다.
- M1 8GB, pyannote.audio 4.0.7, torch 2.14.0 실제 모델 검증: 30초 발췌는 MPS 6.70초, 새 엔진의 60초 발췌는 MPS 8.38초에 완료했다(모델 로드 제외). 둘 다 화자 1명이 검출됐다. 짧은 발췌의 기능 검증이며 다인 정확도나 전체 회의 처리시간을 보장하는 수치가 아니다.
- 검증: GPU 선택, 패딩된 배치의 100% 초과 방지, 클러스터링의 미확정 비율, 프로세스 진행률 전달 및 임시 파일 정리, 전사 재실행 없는 체크포인트 복구. 실제 브라우저에서 데스크톱/390px 모바일, 진행률 갱신, GPU 표시, CPU 전환 안내 확인.
- 공식 참고: [PyTorch MPS](https://docs.pytorch.org/docs/2.14/notes/mps.html), [Community-1 GPU 및 진행률 hook](https://huggingface.co/pyannote/speaker-diarization-community-1/blob/main/README.md).
