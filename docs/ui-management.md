# 읽기 중심 화면과 웹 관리

## 화면 방향

[클로바노트의 PC 기록 흐름](https://help.naver.com/service/24269/contents/12812?lang=ko&osType=PC)과 [음성 기록 편집 방식](https://help.naver.com/service/24269/contents/12829?osType=PC)을 참고했습니다. 회의봇의 짙은 녹색, 아이보리 바탕, 자료 검색·근거 확인 기능은 유지합니다.

- 주요 본문은 16–17px, 보조 설명은 기본 14px 이상으로 조정하고 연한 글자의 대비를 높였습니다.
- 완료된 파일 전사는 업로드 영역을 접어 대본을 먼저 읽을 수 있습니다. ‘다른 파일 올리기’로 다시 펼칩니다.
- 최근 기록은 종류·날짜로 필터링하고 선택한 기록을 표시합니다. 원본 파일이 없을 때 비활성 재생 조작부는 숨깁니다.
- 상단의 파일 전사·실시간 전사·자료 검색과 설정 및 관리는 고정됩니다. 녹음·업로드 도중 설정으로 이동해도 작업을 유지합니다.
- 관리 홈에서 글자 크기와 화면 간격을 변경합니다. 이 브라우저에 저장되고 즉시 적용됩니다.

## 설정 및 관리

`/settings`에 접속하거나 상단 **설정 및 관리**를 누릅니다. 기존 `/rag/settings` 링크도 통합 AI 설정으로 연결됩니다.

| 화면 | 지원 동작 | 적용 시점 |
| --- | --- | --- |
| 음성 인식 | MLX Whisper / Faster Whisper CPU의 Small·Turbo 설치와 선택 | 모델 준비 완료 후 다음 전사부터 |
| 자료 검색 | 임베딩 모델 준비, 청크 크기·겹침·검색 근거 수 저장 | 근거 수는 다음 검색, 청킹은 자료 재색인 후 |
| AI 모델 | 기존 연결 계정·모델·답변 옵션·프롬프트 관리 | 저장 후 다음 답변부터 |
| 설치 및 업데이트 | 운영 환경, 저장 공간, 설치·적용 작업 기록 | 작업 상태를 주기적으로 갱신 |

설치와 적용은 구분됩니다. 새 음성 모델을 적용할 때는 진행 중인 전사가 없어야 하며, 준비에 실패하면 기존 엔진을 유지합니다. 새 설정은 파일·실시간 전사 기본값에 반영됩니다. 사용자가 현재 전사 화면에서 선택한 모델은 같은 기본값을 새로 조회하는 것만으로 덮어쓰지 않습니다.

청크 수는 문서 길이와 청크 크기·겹침에 따라 정해집니다. 사용자가 최종 조각 수를 직접 고정하는 방식은 아닙니다. 설정을 변경한 자료에는 재색인 필요 상태를 표시하고, 완료 전까지 기존 색인으로 검색할 수 있습니다. 다른 창의 변경과 충돌하면 저장을 거절하고 다시 불러오도록 안내합니다. 수정하지 않은 입력은 최신 설정으로 갱신합니다.

## 확인한 범위

- 프론트엔드 빌드 및 47개 단위 테스트 통과.
- STT·런처 회귀 테스트 118개와 별도 엔진 프로세스 테스트 1개 통과.
- RAG 137개 테스트 및 두 Python 프로젝트 Ruff 검사 통과.
- 합성 API를 사용한 관리 브라우저 검사: 직접 경로 진입, 글자 크기 유지, 모델 설치·적용, ISO 설치 날짜, CSRF 설정 저장, 입력 유지, 청크 겹침 검증, 재색인, 임베딩·색인 실패 표시, 다른 창 변경 갱신.
- 관리 화면 5개와 주요 전사·자료 화면을 390/768/1024/1440px에서 확인. 가로 넘침과 상단 잘림 없음.
- 기존 대본 변환·재생·화자 편집·단어 이동·재생 싱크 브라우저 회귀 검사 통과.

실제 대용량 모델 신규 다운로드, Windows/Linux 실기기, Docker 이미지 빌드는 이번 검증에 포함되지 않았습니다. 프로그램 자체 자동 업데이트는 릴리스 채널이 없어 아직 제공하지 않습니다. Community-1 화자 모델 웹 설치, 로컬 LLM 가중치 다운로드, 서명된 OS별 설치 파일도 별도 배포 작업입니다. [설치 경로와 남은 제약](installation.md)을 확인하세요.

## 현재 Mac 반영

진행 중인 전사·색인이 없을 때 기존 코드와 RAG 데이터베이스를 백업하고 상시 서비스를 재시작했습니다. 사용자 모델과 문서 설정은 유지됩니다. RAG 데이터베이스는 추가 설정 테이블이 포함된 스키마 4로 이전하므로 이전 코드로 되돌리려면 업그레이드 전 백업이 필요합니다.
