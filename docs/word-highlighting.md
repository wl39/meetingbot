# 재생 중인 단어 강조

오른쪽 **원본 듣기 → 대본 싱크 → 싱크 켜기 → 현재 단어 강조**를 선택하면 현재 재생 위치의 단어를 노란색으로 표시한다. 기본값은 꺼짐이며, 싱크를 끄면 단어 강조도 중지된다. 싱크를 다시 켜면 같은 화면에서 선택했던 강조 설정을 유지한다.

발화별 보기와 대본 모드 모두 지원한다. 긴 대본에서는 강조 단어가 대본 영역 밖으로 나가면 해당 단어까지 자동으로 스크롤한다. 배속과 앞뒤 이동은 오디오의 실제 재생 시간을 기준으로 따라간다. 일시 정지하면 그 위치를 유지하며, 단어 시간이 있는 대본의 무음 구간과 발화 종료 뒤에는 강조를 없앤다.

현재 단어 강조를 켠 상태에서는 대본의 **아무 단어나 누르면 그 단어의 시작 시점부터 바로 재생**한다. 이미 재생 중이어도 누른 단어로 이동하며, 선택한 단어 구간은 파형에도 표시한다. 키보드 Tab으로 단어를 선택한 뒤 Enter 또는 Space로 재생할 수 있고 모바일 터치도 지원한다. 대본 모드의 화자·시간·▶ 부분은 묶인 대본 처음부터 재생한다. 강조나 싱크를 끄면 단어별 재생 기능도 꺼진다.

## 시간 정보와 한계

- 새로 전사한 발화에는 Whisper가 반환한 단어별 시작·종료 시간을 보존한다. 한국어가 여러 인식 토큰으로 나뉘면 화면의 띄어쓰기 단위로 합쳐 강조한다. 시간 정확도는 음성 인식 모델의 정렬 결과에 따른다.
- 단어별 시간이 없는 기존 기록과 직접 텍스트를 수정한 발화는 각 발화의 길이를 단어 글자 수에 비례해 나누어 표시한다. 이는 추정이며 실제 발음·무음과 다를 수 있다. 이 한계는 옵션 아래에도 안내한다. 기존 기록을 자동 재전사하거나 수정하지 않는다.
- 단어를 눌러 이동하는 위치도 같은 시간 정보를 사용하므로 기존·수정 대본에서는 추정 위치부터 재생한다.
- 텍스트를 수정하면 이전 텍스트의 단어 시간을 제거한다. 화자만 수정하면 단어 시간을 유지하고, 뒤이어 도착한 인식 결과의 시간 변경도 반영한다.
- 표시만 바뀌므로 원래 대본의 공백·문장부호·내보내기 텍스트는 유지된다.

## 저장 호환성과 복구

발화 JSON에 선택적으로 `words: [{text, start_ms, end_ms}]`를 추가했다. 누락된 기존 값은 빈 목록으로 읽는다. SQLite 테이블 구조 변경이나 기존 기록 일괄 변환은 필요 없다. 단어 시간만 바뀌어도 발화 revision과 `changed_fields`를 갱신한다. JSON 내보내기와 이벤트에는 이 추가 필드가 포함된다.

배포 전 STT 서비스가 유휴 상태인지 확인하고 기존 코드·정적 파일 및 SQLite 온라인 백업을 권한 제한된 `.runtime/word-highlight-backups` 아래 저장했다. 실제 경로와 보존 확인 결과는 [배포 기록](word-highlight-deployment.json)에 있다. 실행 중인 STT를 중지한 상태에서 변경한 백엔드 파일 3개를 복사하고 서비스 정의를 유지하여 재시작했다. 정적 파일은 assets를 먼저 복사하고 index.html을 원자적으로 교체했다.

코드 복구가 필요하면 전사 작업이 없는 상태에서 STT를 중지하고 백업의 `backend/app` 내 해당 파일과 `dist-0`을 Meetingbot 실행본에 복원한 뒤 같은 LaunchAgent를 다시 시작한다. `dist-1`은 MeetingbotRAG의 정적 파일 백업이다. 저장 형식은 추가 필드만 사용하므로 코드 복구를 위해 DB를 덮어쓸 필요는 없다. 데이터 복구가 별도로 필요한 경우에만 서비스 중지 후 SQLite 백업을 사용하며, 백업 이후 생성된 기록은 별도 보존한다.

## 검증

- 프론트엔드 41개, STT 백엔드 90개, RAG 116개 테스트 통과. TypeScript 및 배포 빌드, 백엔드 Ruff 검사 통과.
- 실제 Chrome에서 합성 오디오와 모의 API로 두 보기 방식, 옵션 기본값·켜기·끄기·비활성 상태, 정확한 시간·추정 시간, 무음, 역방향 탐색, 수정 중 표시, 긴 대본의 단어 추적, 2배속 및 일시 정지를 확인했다.
- 데스크톱 1440px과 모바일 390px의 화면을 확인했다. 기존 녹음에 대한 실제 발음 정확도를 새로 측정한 것은 아니다.
- UI 검증: `node scripts/stt_script_ui_smoke.mjs`. 이미 실행 중인 정적 배포본은 `STT_UI_BASE`에 주소를 지정해 같은 모의 API 검증을 수행할 수 있다.

실제 Tailscale HTTPS 배포 주소에서도 같은 합성 UI 검증을 통과했다. API는 모두 가로채어 기존 사용자 기록에는 쓰기를 수행하지 않았다.

단어 재생 추가 검증에서는 실제 단어 시간 및 기존 대본의 추정 위치로 클릭 이동, 같은 단어 다시 재생, 대본 모드 안의 다른 발화 선택, 발화별 보기에서의 클릭, Enter/Space, 모바일 터치, 대본 처음부터 재생, 강조·싱크 꺼짐 및 원본 미연결 상태의 비활성을 확인했다. 단어 버튼이 대본 버튼 안에 중첩되지 않아 클릭이 대본 시작으로 다시 이동하지 않는 것도 확인했다. 이번 추가 기능은 정적 화면만 배포하며 서비스 재시작 없이 적용한다. [단어 재생 배포 기록](word-seek-deployment.json).
