# 통합 워크스페이스

- `/`: 파일 전사, `/live`: 실시간 전사, `/rag`: 자료 라이브러리, `/rag/settings`: AI 설정.
- 상단 공통 메뉴는 페이지를 새로 열지 않고 전사/RAG 패널을 전환합니다. 한 번 연 패널은 마운트된 상태로 유지하므로 원본 파일, 대본 보기, 재생 상태, 검색 초안, 선택한 자료와 진행 중인 업로드·녹음이 유지됩니다. 전사와 RAG 사이의 스크롤 위치도 복원합니다.
- 업로드·녹음 중에는 다른 전사 입력 방식으로 바꾸는 버튼만 비활성화합니다. RAG로 이동하거나 원래 전사 화면으로 돌아갈 수 있습니다. 브라우저 뒤로/앞으로 가기도 동일한 규칙을 따릅니다.
- 브라우저 새로고침/닫기는 로컬 파일과 임시 화면 상태를 초기화합니다. 파일 전사와 실시간 전사 사이의 전환은 기존과 같이 현재 전사 선택을 초기화합니다.

## 연결

STT의 `/api/rag/*` 경로가 `STT_RAG_BASE_URL`(기본 `http://127.0.0.1:8766`)로 요청을 전달합니다. RAG 서버의 세션 쿠키, CSRF 검사, 관리자 접속 키를 유지합니다. 서버 관리자 키를 자동으로 삽입하지 않으며, 호출자가 보낸 인증만 전달합니다. 브라우저 Origin은 STT에서 검사한 후 로컬 RAG Origin으로 바꿉니다. Origin이 없는 요청에는 Origin을 만들지 않습니다. 리다이렉트와 환경 프록시는 따르지 않습니다. 전달 요청/응답은 각각 최대 32 MiB이며 RAG의 기존 업로드 한도도 적용됩니다.

브라우저 탭에서 입력한 기존 접속 키는 STT와 RAG 로그인에 함께 사용됩니다. RAG에 유효한 세션 쿠키가 있으면 우선 재사용합니다. 이 설치에서는 두 서비스가 같은 관리자 키 파일을 사용합니다. 서비스별 키가 다른 설치에서는 같은 키 파일을 사용하도록 운영자가 설정해야 통합 로그인이 가능합니다.

기존 `:8766/rag` / `:8443/rag` 링크를 통합 화면으로 보내려면 `.env.rag`에 `RAG_WORKSPACE_URL`을 설정합니다. 값은 경로 없는 STT origin이며, 원격 주소에는 HTTPS가 필요합니다. `/rag/settings` 경로와 링크의 접속 키 fragment도 새 위치로 이어집니다. 비워 두면 RAG 서버가 자체 화면을 제공하므로, 통합 기능은 STT 주소로 접속하세요.

```sh
npm --prefix frontend run build
backend/.venv/bin/python scripts/service.py restart
python3 scripts/rag.py restart
```

적용 전 진행 중인 전사와 RAG 색인 작업이 없는지 확인합니다. 두 서비스는 각자의 실행 환경을 그대로 사용하며 DB 스키마 변경은 없습니다. 기존 배포 코드/정적 파일/설정을 보관하고 복구 시 되돌린 후 해당 서비스를 재시작합니다.

## 검증

프론트엔드 44개, STT 백엔드 102개, RAG 123개 테스트 및 TypeScript/프로덕션 빌드 통과. 프록시 검사는 쿠키/CSRF 전달, 잘못된 Origin 차단, 인증 위임, 파일 바이트·쿼리 보존, 리다이렉트 거부, 서비스 연결 실패와 용량 한도를 포함합니다.

실제 브라우저와 합성 데이터에서 대본 모드 → RAG → 전사 복귀, 원본 WAV 연결 유지, RAG 질문 초안 유지, 뒤로 가기, 실시간 전사 화면 진입을 확인했습니다. 390px 화면에서 두 화면의 가로 넘침이 없고 상단 전환 메뉴가 유지되는 것도 확인했습니다. 실제 마이크 녹음과 외부 AI 전송은 실행하지 않았습니다.
